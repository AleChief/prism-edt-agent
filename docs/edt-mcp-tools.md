# EDT MCP: какие инструменты держать включёнными и как их группировать

Инструкция для человека и для агента. Она не привязана к конкретному компьютеру, клиенту или модели: основные настройки
делаются на стороне сервера EDT MCP и действуют одинаково для Claude Code, Codex, OpenCode, Cline, Cursor и любой модели за ними -
Claude, GPT, DeepSeek, Qwen.

Проверено в ноябре 2026 на плагине `edt-mcp-server` 2.22.1 (EDT 2026.1.2). В другой версии плагина число и состав инструментов
могут отличаться - сверяйтесь со счётчиком на вкладке «Инструменты» и с ответом `list_toolsets`.

## Зачем это нужно

Сервер отдаёт 102 инструмента, их описания занимают 118 КБ - около 33 тыс. токенов. Клиент передаёт этот список модели
целиком в каждом запросе, поэтому длинный список - это постоянный расход и лишний шум для модели.

Замеры на 20 задачах PRISM (категория B, агент Claude Code в режиме без диалога, восемь моделей) - в статье
[«Модель или обвязка: что решает, когда ИИ-агент пишет код 1С через EDT»](https://infostart.ru/1c/articles/2858222/)
и в [сводке результатов](results.md). Коротко:

- **Полный список - чистый расход.** Вход в три-четыре раза больше, чем на шестнадцати, качество не выше. Из 86 дополнительных инструментов за 60 задач модели вызвали два.
- **Сокращение списка** экономит вход, но качества само по себе не прибавляет. Сильным моделям сырые инструменты почти ничего не дают: Opus без инструментов решает не меньше, чем с ними.
- **Встроенные группы сервера не экономят** - вход в полтора-два раза больше, чем на шестнадцати (подробности в разделе 2А).
- **Составные инструменты** (один вызов вместо цепочки) сокращают вход в два-шесть раз всем облачным моделям, а средним ещё и прибавляют качество (Haiku с 15,7 до 19,3, MiniMax с 14,3 до 18,7). Качество надёжнее всего даёт запуск кода на тестовой базе.

Отсюда два подхода, их можно сочетать:

- **Вариант 1 - отключение.** Постоянный набор для регулярной работы, остальные инструменты выключены и включаются под задачу.
- **Вариант 2 - группировка.** Модель видит только нужные группы инструментов или несколько составных инструментов вместо десятков мелких.

## Где что настраивается

| Место | Что там делают | На кого действует | От клиента и модели зависит? |
|---|---|---|---|
| **Сервер: окно EDT** - Preferences → MCP Server → вкладка «Инструменты» | галочки инструментов, список «Пресет», счётчик «Включено N из M» | на всех, кто подключён к этой EDT | нет |
| **Сервер: файл настроек** рабочей области | ключи `mcpDisabledTools`, `mcpToolPresetId`, `mcpProgressiveDisclosure`, `mcpServerPort` | на всех, кто подключён к этой EDT | нет |
| **Обёртка** - свой MCP-сервер поверх EDT MCP | составные инструменты | на того, кому подключена обёртка вместо сервера EDT | нет, нужен только клиент с поддержкой MCP |
| **Клиент** - Claude Code, Codex и другие | списки разрешённых и запрещённых инструментов, роли | на одну сессию, роль или запуск | да, у каждого клиента свои ключи |

Начинать стоит с сервера: это работает везде одинаково. Настройки клиента - дополнение, когда разным исполнителям нужны разные наборы.

Файл настроек сервера - у каждой рабочей области EDT свой, путь одинаков в любой операционной системе:

```
<рабочая область>/.metadata/.plugins/org.eclipse.core.runtime/.settings/com.ditrix.edt.mcp.server.prefs
```

**Правило для файла: править только при закрытой EDT.** Открытая EDT при выходе перезапишет файл своими значениями.
Порядок: закрыть EDT → сделать копию файла → поправить → запустить EDT → проверить (раздел «Как проверить»).

Отключённый на сервере инструмент не просто скрыт - сервер отказывает в вызове:
`Tool '…' is disabled by the user … EDT Preferences → MCP Server → Tools tab`.

Адрес сервера и готовую запись для клиента даёт сама EDT: Preferences → MCP Server → вкладка «Общие» → кнопки
«Скопировать адрес» и «Скопировать конфигурацию». По умолчанию адрес - `http://127.0.0.1:8765/mcp`.
Порт у каждой рабочей области свой - как и зачем его менять, в следующем разделе.

## Порт сервера и несколько EDT одновременно

Каждая запущенная EDT поднимает свой сервер MCP на своём порту. По умолчанию это 8765, и пока EDT одна, менять его незачем.

### Зачем менять порт

- **Запуск нескольких EDT.** Один порт может слушать только один процесс. Вторая EDT с тем же портом свой сервер не поднимет, а клиент по этому адресу попадёт в первую EDT - то есть в чужую рабочую область и чужие проекты.
- **Порт занят другой программой** - сервер не стартует, пока порт не сменить.

Когда нужны несколько EDT:

- **Параллельная работа.** Несколько агентов или человек и агент работают одновременно, у каждого своя рабочая область: правки, построение проекта и загрузка в базу одного не мешают другому.
- **Разные проекты или ветки** разложены по разным рабочим областям.
- **Разные наборы инструментов.** Список включённых инструментов и раскрытые группы - свои у каждой рабочей области. Одна EDT может держать набор для разработки, другая - для отладки или только для чтения.

Правило: **одна рабочая область - один постоянный порт.** Заведите список и не меняйте его без нужды, иначе придётся править настройки всех клиентов:

| Рабочая область | Порт | Для чего |
|---|---|---|
| основная | 8765 | разработка |
| вторая | 8766 | второй агент или другая ветка |
| третья | 8767 | отладка, эксперименты |

### Как поменять порт

- **В окне EDT:** Preferences → MCP Server → вкладка «Общие» → поле «Порт сервера» → Apply → кнопка «Перезапустить». Перезапускается только сервер MCP, не сама EDT. Рядом видно состояние: «Работает на порту N», а до перезапуска - «(порт N - после перезапуска)».
- **В файле настроек** рабочей области, при закрытой EDT:
  ```
  mcpServerPort=8766
  mcpServerAutoStart=true
  ```
  Для новой рабочей области эти строки удобно записать до первого запуска EDT - тогда она сразу поднимется на своём порту и не столкнётся с уже открытой (проверено). Автозапуск в новой рабочей области может быть выключен, поэтому вторая строка нужна.
- **Переменными окружения** при запуске EDT: в плагине есть `EDT_MCP_PORT` и `EDT_MCP_AUTO_START`; их действие здесь не проверялось.

Вторая EDT запускается с указанием своей рабочей области: `1cedt -data <путь к рабочей области>`. Одну рабочую область открывает только один экземпляр EDT.

### Что поменять у клиента

Каждая EDT - отдельный сервер MCP со своим именем и адресом.

Claude Code, файл `.mcp.json`:

```json
{
  "mcpServers": {
    "edt":  {"type": "http", "url": "http://127.0.0.1:8765/mcp"},
    "edt2": {"type": "http", "url": "http://127.0.0.1:8766/mcp"}
  }
}
```

Codex CLI, файл `~/.codex/config.toml`:

```toml
[mcp_servers.edt]
url = "http://127.0.0.1:8765/mcp"

[mcp_servers.edt2]
url = "http://127.0.0.1:8766/mcp"
```

Обёртке адрес передаётся ключом `--url`.

Что учесть:

- **Имя сервера входит в имя инструмента.** В Claude Code это `mcp__edt2__write_module_source`, поэтому списки запретов и поле `tools:` ролей пишутся с именем нужного сервера.
- **Подключайте исполнителю только ту EDT, с которой он работает.** Две подключённые EDT - это два списка инструментов и двойной расход, а модель может перепутать, в какую из них писать.
- **Каждая EDT - отдельный процесс** и занимает память: от половины гигабайта на маленьком проекте до нескольких гигабайт на большой конфигурации.
- **Сервер слушает только локальный адрес.** Удалённый доступ - отдельная настройка с токеном; для нескольких EDT на одном компьютере она не нужна.

### Как проверить, в какую EDT попали

- `get_server_status` - поле `port`;
- `list_projects` - проекты именно этой рабочей области.

Агенту: перед правками убедиться по `list_projects`, что подключён к своей рабочей области; порт и адрес брать из задания или настроек, а не подбирать перебором.

## Вариант 1. Набор для регулярной работы

Регулярная работа - правка кода и метаданных, проверка ошибок, загрузка в базу, прогон тестов. Для неё оставлены 30 инструментов
из 102: описания 42 КБ вместо 118 КБ, примерно 12 тыс. токенов вместо 33 тыс.

Набор измерен на задачах по коду (три прогона): качество на уровне шестнадцати инструментов (Opus 18,7, Haiku 15,7, DeepSeek 18,3),
вход почти вдвое больше (Opus 61 → 111 тыс. токенов на задачу). Дополнительные 14 инструментов нужны для реальной разработки -
метаданные, загрузка в базу, тесты, синхронизация с диском; если работаете только с кодом, шестнадцати хватит.
Подстройте набор под себя: если инструмент из «отключить» нужен каждый день - оставьте его.

Таблицы ниже - по группам сервера (их показывает `list_toolsets`). В окне EDT галочки разложены по другим заголовкам
(«Core / Project», «Errors & Problems», «Applications & Testing»…), имена инструментов те же.

Столбец «Режим»: **оставить** - входит в постоянный набор; **отключить** - выключен, включается под задачу из последнего столбца.

### Как включить что-то под задачу и вернуть обратно

Человек:
1. EDT → Preferences → MCP Server → вкладка «Инструменты».
2. Поставить галочки нужным инструментам или целой группе → Apply. Перезапуск EDT не нужен.
3. Сервер рассылает клиентам уведомление об изменении списка. Claude Code подхватывает его в открытой сессии; если в вашем клиенте инструмент не появился - переподключите сервер или начните новую сессию.
4. После задачи снять галочки.

Агент:
1. Настройки сервера сам не меняет. Получив отказ `is disabled by the user`, называет пользователю инструмент или группу из таблиц выше и задачу, для которой он нужен.
2. Править файл настроек может только по прямой просьбе и только при закрытой EDT.
3. В итоге работы пишет, какие инструменты были включены дополнительно, чтобы их можно было выключить.

без правки кода и отладки), `code-review` (анализ и чтение кода, без записи), `development` (полная разработка без отладки),

Состав пресетов по инструментам здесь не проверялся - после выбора смотрите счётчик «Включено N из M». Набор из 30 - это `custom`.

## Вариант 2. Группировка

Три способа, от простого к трудоёмкому. Первый и третий не зависят от клиента и модели.

### 2А. Встроенные группы сервера - постепенное раскрытие

Сервер умеет показывать только группу `core` и раскрывать остальные по запросу модели. Проверено:

- при включённом режиме сервер отдаёт 12 инструментов, 7,8 КБ вместо 118 КБ;
- модель вызывает `list_toolsets`, затем `enable_toolset(toolsets=["code"])` - и группа появляется в списке;
- DeepSeek в Claude Code проделал это сам по одной фразе в задании и вызвал инструмент из раскрытой группы в той же сессии.

Группы сервера (состав задан плагином, изменить его нельзя):

| Группа | Инструментов | Описания, КБ | Что внутри |
|---|---|---|---|
| `core` | 12 | 7,7 | навигация, чтение модулей и метаданных, управление группами; видна всегда |
| `code` | 9 | 8,2 | запись кода, чтение метода, ссылки, определения, проверка запроса |
| `project` | 29 | 37,7 | ошибки проекта, справка платформы, синхронизация, загрузка в базу, базы, проекты, ветки |
| `metadata` | 16 | 27,6 | создание и правка метаданных, СКД, подсистемы, конфигурации запуска |
| `debug` | 15 | 15,5 | запуск, точки останова, шаги, переменные |
| `testing` | 5 | 6,2 | YAxUnit, фоновые задания, 1С:Напарник |
| `comparison` | 3 | 5,0 | сравнение и правила слияния |
| `translation` | 3 | 2,3 | словари Language Tool |
| `forms` | 4 | 2,2 | расположение и снимки форм и макетов, проверка формы |
| `profiling` | 3 | 2,1 | замер производительности |
| `tags` | 2 | 0,8 | метки объектов |
| `git` | 1 | - | команды git; выключена по умолчанию |

Как включить режим:

- В окне настроек плагина 2.22.1 переключателя нет. Включается ключом в файле настроек (при закрытой EDT):
  ```
  mcpProgressiveDisclosure=true
  ```
- В плагине есть и переменная окружения `EDT_MCP_PROGRESSIVE_DISCLOSURE` для запуска EDT; её действие здесь не проверялось.

Что важно знать:

- **Видимость групп общая для сервера.** Группу, раскрытую одним агентом, видят все клиенты этой EDT; при закрытии сессии она остаётся раскрытой. Закончив, агент скрывает её: `enable_toolset(toolsets=[…], disable=true)`.
- **Скрытая группа - не запрет.** Скрытый инструмент можно вызвать по имени, он выполнится. Запрещает только `mcpDisabledTools`.
- **Оба механизма складываются.** Инструмент из `mcpDisabledTools` не появляется и в раскрытой группе, вызов отклоняется.
- **Состояние групп в файл не пишется**, оно живёт в памяти сервера. После перезапуска EDT, судя по этому, остаётся одна `core` (перезапуском не проверялось).
- **Клиент должен обновлять список инструментов.** Сервер шлёт уведомление `notifications/tools/list_changed`. Claude Code его обрабатывает; в другом клиенте проверьте на пробной задаче. Если клиент список не обновляет, режим для него бесполезен - берите вариант 1.
- **Группа `project` тяжёлая и разнородная:** рядом с `get_project_errors` в ней `delete_project` и `delete_infobase`. Поэтому режим сочетают с `mcpDisabledTools`.
- **Цена - выше, чем кажется.** Замер (по три прогона): вход на задачу в полтора-два раза больше, чем на фиксированных 16 инструментах - Opus 61 → 125 тыс. токенов,
  Haiku 77 → 149, DeepSeek 79 → 182; качество то же (19,0 → 19,0; 15,7 → 15,3; 17,7 → 17,3). Причины: группы крупные - ради проверки ошибок
  модель открывает `project` на 29 инструментов; после раскрытия список меняется, и кэш запроса сбрасывается; на само раскрытие уходят
  лишние вызовы (8-15 на задачу против 6-11). Слабой модели в задании прямо пишут, какие группы открыть.

Когда режим оправдан: задачи разнородные и заранее неизвестно, понадобится ли отладка, метаданные или тесты. Для потоковой работы над
кодом фиксированный короткий набор (вариант 1) дешевле в полтора-два раза. Если включаете режим - сочетайте его с `mcpDisabledTools` для опасных
и ненужных инструментов (удаление проектов и баз, git, устаревшие), а `list_toolsets` и `enable_toolset` из списка отключённых уберите.

### 2Б. Роли - группировка на стороне клиента

Сервер отдаёт широкий набор, а каждому исполнителю достаётся своя часть. Ключи у каждого клиента свои; общее правило одно:
клиент не может дать то, что отключено на сервере.

Примеры ролей:

| Роль | Инструменты |
|---|---|
| правка кода | `get_metadata_objects`, `get_metadata_details`, `get_module_structure`, `read_module_source`, `read_method_source`, `write_module_source`, `get_project_errors`, `validate_query`, `get_platform_documentation`, `get_tool_guide` |
| разбор кода, только чтение | чтение метаданных и модулей, `search_in_code`, `read_method_source`, `find_references`, `go_to_definition`, `get_method_call_hierarchy`, `get_symbol_info` |
| метаданные и формы | чтение метаданных, `create_metadata`, `modify_metadata`, `adopt_metadata_object`, `validate_form_model`, `get_project_errors`, `resync_to_disk`, `get_tool_guide` |
| тесты и загрузка в базу | `infobase_sessions`, `update_database`, `run_yaxunit_tests`, `get_job_status`, `get_project_errors` |
| отладка | группа `debug` целиком, `read_method_source`, `get_module_structure` |

**Claude Code** (проверено на версиях 2.1.323-2.1.325). Имя инструмента в настройках - `mcp__<имя сервера>__<инструмент>`.

Роль - файл агента `.claude/agents/<имя>.md` в проекте или `~/.claude/agents/<имя>.md` для всех проектов.
Поле `tools:` - белый список: агент видит только перечисленное.

```markdown
---
name: edt-coder
description: Правка кода модулей 1С в проекте EDT и проверка ошибок
tools: mcp__edt__get_metadata_objects, mcp__edt__get_metadata_details, mcp__edt__get_module_structure, mcp__edt__read_module_source, mcp__edt__read_method_source, mcp__edt__write_module_source, mcp__edt__get_project_errors, mcp__edt__validate_query, mcp__edt__get_platform_documentation, mcp__edt__get_tool_guide
---
Ты правишь код 1С в проекте EDT только через инструменты сервера edt.
```

Модель при этом может быть любой: Claude Code работает и с другими моделями через совместимый адрес (`ANTHROPIC_BASE_URL`),
так на нём проверялись DeepSeek, MiniMax и Qwen.

| Способ в Claude Code | Где задаётся | Прячет от модели |
|---|---|---|
| поле `tools:` агента | файл агента; для запуска без диалога - `--agents '{…}' --agent <имя>` | да, белый список |
| `permissions.deny: ["mcp__edt__имя", …]` | `.claude/settings.json`, `settings.local.json`, `--settings <файл>` | да |
| `--disallowedTools mcp__edt__имя,…` | ключ запуска | да |
| `--mcp-config <файл> --strict-mcp-config` | ключ запуска | да, подключены только серверы из файла |
| `--allowedTools` | ключ запуска | **нет**: модель видит всё, вызов неразрешённого получает отказ |
| запись в файле инструкций «пользуйся только такими-то» | `CLAUDE.md` | **нет**: описания остаются в контексте, слабая модель правило не соблюдает |

**Codex CLI.** Серверы MCP описываются в `~/.codex/config.toml`; у сервера есть белый и чёрный списки инструментов.
Ключи приведены по документации Codex на ноябрь 2026 и на практике здесь не проверялись - сверьте со своей версией:

```toml
[mcp_servers.edt]
url = "http://127.0.0.1:8765/mcp"
enabled_tools = ["get_metadata_objects", "get_metadata_details", "get_module_structure", "read_module_source",
                 "read_method_source", "write_module_source", "get_project_errors", "validate_query",
                 "get_platform_documentation", "get_tool_guide"]
# disabled_tools = ["delete_project", "delete_infobase"]   # чёрный список, применяется после белого
# enabled = false                                          # отключить сервер, не удаляя запись
```

Отдельных ролей с разными наборами в одном файле настроек у Codex нет; разные наборы получают разными файлами настроек
(профили) или обёрткой.

**Другие клиенты** (OpenCode, Cline, Cursor, VS Code). Ищите в их документации два свойства: список разрешённых или запрещённых
инструментов у сервера MCP и возможность задать его для отдельного режима или агента. Если клиент не умеет ни того ни другого -
остаются настройки сервера (вариант 1, 2А) и обёртка (2В), им клиент безразличен.

Проверка одна для всех: запретите пробный инструмент и посмотрите, остался ли он в списке, который клиент показывает модели.
Запрет, который оставляет инструмент в списке, токенов не экономит.

### 2В. Составные инструменты - обёртка

Составной инструмент за один вызов делает несколько вызовов EDT и возвращает склеенный ответ: например, «записать модуль и сразу
вернуть ошибки со строками кода». Настройками этого не получить: обёртка - отдельный небольшой MCP-сервер, который клиент запускает
как обычную программу. Он подходит любому клиенту с поддержкой MCP и любой модели.

Готовый пример - в приложении в конце документа: один файл на Python без сторонних библиотек, три инструмента. Он проверен
на рабочем сервере EDT MCP; описания его инструментов занимают 1,1 КБ.

| Составной инструмент | Что делает внутри |
|---|---|
| `inspect_objects` | `get_metadata_details` по списку объектов и, если задан путь, `read_module_source` |
| `write_and_check` | `write_module_source` → ожидание перепроверки → `get_project_errors`; ошибки возвращает вместе со строками кода |
| `check_query` | `validate_query`; в ответе только ошибки со строками запроса |

Что ещё обычно добавляют: справку платформы (`get_platform_documentation` с обрезкой длины), образцы типовых приёмов из своего файла,
правку одного метода вместо перезаписи модуля, запуск кода или тестов.

Как подключить. Сохраните код из приложения в файл `edt_compose.py`. Исполнителю подключают обёртку **вместо** сервера EDT,
а не рядом с ним - иначе модель увидит оба списка.

Claude Code - файл `.mcp.json` в проекте или отдельный файл для `--mcp-config`:

```json
{
  "mcpServers": {
    "edt": {
      "command": "python",
      "args": ["/путь/к/edt_compose.py", "--url", "http://127.0.0.1:8765/mcp", "--project", "ИмяПроектаEDT"]
    }
  }
}
```

Запуск без диалога, чтобы подключились только серверы из файла: `claude -p --mcp-config <файл> --strict-mcp-config`.

Codex CLI - `~/.codex/config.toml`:

```toml
[mcp_servers.edt]
command = "python"
args = ["/путь/к/edt_compose.py", "--url", "http://127.0.0.1:8765/mcp", "--project", "ИмяПроектаEDT"]
```

Правила для своей обёртки:
- **Успех записи определять по ответу сервера**, а не по отсутствию ошибок: при незакрытых блоках EDT модуль не пишет, прежний текст остаётся, и проверка по нему ошибок не покажет.
- **Ждать окончания построения проекта:** пока EDT строит проект, она отвечает `Project is building`, а не списком ошибок.
- **Ошибку возвращать вместе со строкой кода**, к которой она относится, и с указанием, что делать дальше.
- **Проверять то, чего EDT не ловит:** выдуманные аннотации вроде `&Экспортная`, отсутствие слова `Экспорт` у функции, которую вызывают снаружи. На локальной модели такая проверка подняла результат с 15,3 до 17,3 из 20.
- **Закрывать сессии:** сервер EDT MCP копит открытые сессии до своего предела, после чего отказывает всем.
- **Запуск кода или тестов - один раз в конце** и с правилом остановки в задании, иначе модель перепроверяет до предела времени.
- **Не ставить штраф за повторы** (`repeat penalty` выше 1,0) локальной модели: в коде 1С идентификаторы обязаны повторяться, и модель начинает их портить.

## Что выбрать

| Кто работает | Что делать |
|---|---|
| Сильная модель в диалоге с человеком (Claude Opus, Sonnet, GPT) | вариант 1: набор на сервере (16 для работы с кодом, 30 для разработки с метаданными и тестами), остальное включать под задачу. 2А - только если задачи разнородные: расход в полтора-два раза выше |
| Вспомогательные агенты и роли | 2Б: белый список инструментов на роль |
| Дешёвый исполнитель без диалога (DeepSeek, Claude Haiku, MiniMax) | 2В, обёртка: лучшее качество и наименьший вход. Пока обёртки нет - 2Б с ролью «правка кода» |
| Локальная или слабая модель (Qwen и подобные) | только 2В, с запуском кода и проверкой объявлений; сокращение списка без обёртки ей не помогает |
| Полный набор из 102 | никому: вход в три-четыре раза больше при том же качестве |

## Как проверить

- **В окне EDT:** вкладка «Инструменты», счётчик «Включено N из M».
- **Запросом к серверу:** `get_server_status` - поля `enabledTools` и `totalTools`; `list_toolsets` - поле `progressiveDisclosure` и признак `visible` у групп.
- **Что видит модель в Claude Code:** в диалоге - `/mcp` → сервер → список инструментов; без диалога - `claude -p --output-format stream-json --verbose`, первое событие `init` содержит список `tools`.
- **Что видит модель в Codex:** `/mcp` в диалоге, `codex mcp list` в командной строке.
- **Расход:** сравните вход первого запроса до и после настройки - он должен упасть на размер убранных описаний.

## Памятка агенту

1. Перед работой с EDT MCP посмотреть, какие инструменты доступны; не вызывать и не просить то, что не нужно задаче.
2. Параметры инструмента брать из `get_tool_guide('<имя>')`, а не угадывать: короткие описания их не содержат.
3. Отказ `is disabled by the user` не обходить: назвать инструмент, группу и задачу, попросить включить.
4. При постепенном раскрытии: `list_toolsets` → `enable_toolset` → работа → скрыть группу обратно (`disable=true`), потому что видимость общая для всех клиентов этой EDT.
5. Файл настроек сервера не править при открытой EDT и без просьбы человека; чужие рабочие области не трогать.
6. Опасные инструменты (`update_database`, `delete_*`, `rename_metadata_object`, `clean_project`) - только по задаче и после проверки условий: в базе никто не работает, несохранённой работы нет.

## Приложение. Код обёртки `edt_compose.py`

Python 3.9 или новее, сторонние библиотеки не нужны. Параметры запуска: `--url` - адрес сервера EDT MCP, `--project` - имя проекта EDT.

```python
"""MCP-сервер-обёртка (stdio) поверх EDT MCP: три составных инструмента вместо десятков мелких.

Запуск: python edt_compose.py --url http://127.0.0.1:8765/mcp --project ИмяПроекта
"""
import argparse
import json
import re
import sys
import time
import urllib.request

HEADERS = {"Content-Type": "application/json", "Accept": "application/json, text/event-stream"}

TOOLS = [
    {"name": "inspect_objects",
     "description": "Показать состав объектов метаданных (реквизиты, табличные части, типы) и, если задан modulePath, текст модуля. "
                    "Вызывай до написания кода: имена берутся только отсюда.",
     "inputSchema": {"type": "object", "required": ["objectFqns"], "properties": {
         "objectFqns": {"type": "array", "items": {"type": "string"}, "description": "например [\"Catalog.Номенклатура\"]"},
         "modulePath": {"type": "string", "description": "например CommonModules/ОбщегоНазначения/Module.bsl"}}}},
    {"name": "write_and_check",
     "description": "Записать модуль ЦЕЛИКОМ (прежний текст заменяется) и сразу проверить. Возвращает «Ошибок нет» "
                    "либо список ошибок с номерами строк и самими строками кода.",
     "inputSchema": {"type": "object", "required": ["modulePath", "source"], "properties": {
         "modulePath": {"type": "string"}, "source": {"type": "string", "description": "полный текст модуля"}}}},
    {"name": "check_query",
     "description": "Проверить текст запроса 1С на объектах проекта: синтаксис, имена таблиц и полей.",
     "inputSchema": {"type": "object", "required": ["queryText"], "properties": {"queryText": {"type": "string"}}}},
]


def post(url, body, session=None):
    headers = dict(HEADERS, **({"Mcp-Session-Id": session} if session else {}))
    with urllib.request.urlopen(urllib.request.Request(url, json.dumps(body).encode(), headers), timeout=600) as r:
        sid = r.headers.get("Mcp-Session-Id") or session
        raw = r.read().decode("utf-8", "replace")
    if raw.lstrip().startswith("{"):
        return sid, json.loads(raw)
    data = [line[5:].strip() for line in raw.splitlines() if line.startswith("data:")]  # ответ пришёл потоком событий
    return sid, json.loads(data[-1]) if data else None


def edt(url, tool, **args):
    """Один вызов инструмента EDT MCP. Сессия закрывается: сервер копит открытые сессии до своего предела."""
    sid, _ = post(url, {"jsonrpc": "2.0", "id": 1, "method": "initialize", "params": {
        "protocolVersion": "2025-03-26", "capabilities": {}, "clientInfo": {"name": "edt-compose", "version": "1"}}})
    try:
        post(url, {"jsonrpc": "2.0", "method": "notifications/initialized"}, sid)
        _, res = post(url, {"jsonrpc": "2.0", "id": 2, "method": "tools/call", "params": {"name": tool, "arguments": args}}, sid)
    finally:
        try:
            urllib.request.urlopen(urllib.request.Request(url, method="DELETE", headers={"Mcp-Session-Id": sid}), timeout=10).close()
        except OSError:
            pass
    result = (res or {}).get("result") or {}
    if result.get("structuredContent") is not None:
        return json.dumps(result["structuredContent"], ensure_ascii=False)
    return "\n".join((p.get("resource") or {}).get("text") or p.get("text") or "" for p in result.get("content") or [])


def inspect_objects(url, project, fqns, module_path):
    out = edt(url, "get_metadata_details", projectName=project, objectFqns=fqns)
    if module_path:
        out += "\n\n# Текст модуля " + module_path + "\n" + edt(url, "read_module_source", projectName=project, modulePath=module_path)
    return out


def write_and_check(url, project, module_path, source):
    written = edt(url, "write_module_source", projectName=project, modulePath=module_path, source=source, mode="replace", overwrite=True)
    if "status: success" not in written:  # при незакрытых блоках EDT модуль не пишет, прежний текст остаётся
        return "Модуль НЕ записан, прежний текст остался. Исправь и запиши снова.\n" + written[:1500]
    owner = module_path.split("/")[1]  # CommonModules/<Имя>/Module.bsl -> <Имя>
    for _ in range(40):
        time.sleep(3)  # EDT перепроверяет модуль после записи; пока проект строится, ошибки не отдаются
        errors = edt(url, "get_project_errors", projectName=project, severity="ERRORS", objects=[owner], responseFormat="detailed")
        if "Project is building" not in errors:
            break
    rows = re.findall(r"^\| (.+?) \| [^|]* \| [^|]* \| (\d+) \|", errors, re.M)  # | описание | объект | путь | строка | …
    if "No Errors Found" in errors:
        return "Модуль записан. Ошибок нет."
    if not rows:
        return "Модуль записан, но есть ошибки:\n" + errors[:3000]
    lines = source.splitlines()
    out = ["Модуль записан, но в нём есть ошибки. Исправь именно эти места и запиши модуль снова."]
    for message, number in sorted(rows, key=lambda r: int(r[1])):
        n = int(number)
        out.append(f"- строка {n}: {message}" + (f"\n      {lines[n - 1].strip()}" if 0 < n <= len(lines) else ""))
    return "\n".join(out)


def check_query(url, project, query):
    raw = edt(url, "validate_query", projectName=project, queryText=query)
    try:
        issues = [i for i in json.loads(raw).get("issues", []) if i.get("severity") == "ERROR"]
    except ValueError:
        return raw[:2000]
    if not issues:
        return "Запрос верен."
    lines = query.splitlines()
    return "В запросе ошибки:\n" + "\n".join(
        f"- строка {i.get('line')}: {i.get('message')}" + (f"\n      {lines[i['line'] - 1].strip()}" if 0 < (i.get("line") or 0) <= len(lines) else "")
        for i in issues)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--url", default="http://127.0.0.1:8765/mcp")
    ap.add_argument("--project", required=True)
    args = ap.parse_args()
    sys.stdin.reconfigure(encoding="utf-8")
    sys.stdout.reconfigure(encoding="utf-8")

    def send(obj):
        sys.stdout.write(json.dumps(obj, ensure_ascii=False) + "\n")
        sys.stdout.flush()

    for line in sys.stdin:
        try:
            msg = json.loads(line)
        except ValueError:
            continue
        mid, method, params = msg.get("id"), msg.get("method"), msg.get("params") or {}
        if method == "initialize":
            send({"jsonrpc": "2.0", "id": mid, "result": {"protocolVersion": params.get("protocolVersion", "2025-03-26"),
                                                         "capabilities": {"tools": {}}, "serverInfo": {"name": "edt-compose", "version": "1"}}})
        elif method == "tools/list":
            send({"jsonrpc": "2.0", "id": mid, "result": {"tools": TOOLS}})
        elif method == "tools/call":
            name, a = params.get("name"), params.get("arguments") or {}
            try:
                if name == "inspect_objects":
                    text = inspect_objects(args.url, args.project, a.get("objectFqns") or [], a.get("modulePath"))
                elif name == "write_and_check":
                    text = write_and_check(args.url, args.project, str(a.get("modulePath", "")), str(a.get("source", "")))
                elif name == "check_query":
                    text = check_query(args.url, args.project, str(a.get("queryText", "")))
                else:
                    text = f"неизвестный инструмент: {name}"
                send({"jsonrpc": "2.0", "id": mid, "result": {"content": [{"type": "text", "text": text}]}})
            except Exception as exc:  # сбой обёртки не должен ронять сессию агента
                send({"jsonrpc": "2.0", "id": mid, "result": {"content": [{"type": "text", "text": f"Сбой обёртки: {exc!r}"}], "isError": True}})
        elif mid is not None:
            send({"jsonrpc": "2.0", "id": mid, "error": {"code": -32601, "message": "method not found"}})


if __name__ == "__main__":
    main()
```
