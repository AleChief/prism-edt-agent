# prism-edt-agent

Агентный стенд для категории B бенчмарка PRISM: модель решает задачу не одним ответом, а как агент в проекте 1С:EDT
через EDT MCP - смотрит метаданные, пишет модуль, читает ошибки и исправляется. Решение проверяется скрытыми тестами
PRISM на локальной платформе 1С, без Docker.

Стенд меняет не только модель, но и набор инструментов агента: от «без инструментов» до всех 102 инструментов EDT MCP,
и отдельно - обёртку из нескольких составных инструментов. Результаты и выводы - в статье на Инфостарте:
[«Модель или обвязка: что решает, когда ИИ-агент пишет код 1С через EDT»](https://infostart.ru/1c/articles/2858222/),
сводка - в [docs/results.md](docs/results.md). Как настроить набор инструментов EDT MCP у себя, не запуская стенд, -
в [docs/edt-mcp-tools.md](docs/edt-mcp-tools.md).

## Что внутри

| Путь | Что это |
|---|---|
| `bench.py` | единая точка входа: проверка, подготовка, переключение наборов, серии, оценка, отчёт |
| `settings.example.yaml` | пример настроек: все пути, порты, сервер модели и параметры теста |
| `stand/agent.py` | один прогон задачи агентом (Claude Code CLI без окна) |
| `stand/series.py` | серия: модели × задачи × прогоны, повтор сбоев, оценка |
| `stand/scorer.py` | оценщик: сборка прогонной конфигурации PRISM, база через ibcmd, скрытые тесты в клиенте 1С |
| `stand/mcp_server.py` | **обёртка** - MCP-сервер с составными инструментами поверх EDT MCP и запуском кода |
| `stand/variants.py` | варианты теста: какие инструменты видит агент и какое условие получает |
| `stand/edt_mode.py` | переключение набора инструментов сервера EDT MCP (16, 30, 102, группы) |
| `stand/prepare.py` | исходники проектов задач и рабочая область EDT с проектами |
| `stand/check.py` | проверка готовности стенда |
| `stand/report.py` | отчёт: решено по прогонам, токены, вызовы, время, цена задачи |
| `tasks/` | девять новых задач B21–B29 в формате PRISM |
| `docs/results.md` | сводка результатов из статьи |
| `docs/edt-mcp-tools.md` | инструкция по EDT MCP: назначение каждого из 102 инструментов, наборы, встроенные группы, роли на стороне клиента, порты для нескольких EDT, пример обёртки |

Задачи B1–B20 стенд берёт из клона PRISM, в репозитории их нет.

## Требования

| Компонент | Версия, на которой снято | Зачем |
|---|---|---|
| Windows | 10/11 | платформа 1С, EDT, блокировки файлов (`msvcrt`) |
| Python | 3.12 (подходит 3.10+) | стенд и PRISM |
| PRISM | коммит `9426bc1` от 30.10.2026 | задачи B1–B20, сборщик конфигураций, разбор вердикта |
| 1С:Предприятие 8.3 | 8.3.27.2214 | `ibcmd` (базы без лицензии), конфигуратор и тонкий клиент для тестов |
| Лицензия 1С | хотя бы одна свободная | одна оценка держит одну лицензию около двух минут |
| 1С:EDT | 2026.1.2 | проекты задач |
| Плагин EDT MCP | 2.22.1 | инструменты агента; другие версии могут отдавать другое число инструментов |
| Claude Code CLI | 2.1.33x | агент (`claude -p`) |
| Модель | любая с API Anthropic Messages | напрямую, по подписке Claude Code или через шлюз |

Агентом служит Claude Code. Подключить другой клиент (Cursor, Cline, OpenCode) можно: инструменты - обычные MCP-серверы
(EDT MCP по HTTP и `stand/mcp_server.py` по stdio), а условия задач лежат в `stand/variants.py`. Но запуск такого клиента
и разбор его журнала придётся написать самим.

## Установка

1. **PRISM.** Клонировать и поставить в тот же Python, что и стенд:
   ```
   git clone https://github.com/genlab-1c/prism C:\tools\prism
   pip install -e C:\tools\prism
   ```
   Путь к клону - `paths.prism` в настройках. Docker для стенда не нужен.
2. **Стенд.**
   ```
   git clone https://github.com/AleChief/prism-edt-agent
   cd prism-edt-agent
   copy settings.example.yaml settings.yaml
   ```
   В `settings.yaml` поправить пути к PRISM, платформе, EDT и рабочей области, порт EDT MCP и сервер модели.
3. **EDT и плагин.** Установить 1С:EDT и плагин EDT MCP. Рабочую область заводить не нужно: `bench.py prepare`
   создаст её по пути из настроек и пропишет порт плагина.
4. **Ключ модели** - только переменной окружения, имя которой задано в `agent.api_key_env`:
   ```
   setx ANTHROPIC_API_KEY "<ключ>"
   ```
   Для сторонних моделей - ключ шлюза и его адрес в `agent.base_url`. По подписке Claude Code ключ не нужен:
   `agent.auth: subscription` и вход через `claude login`.
5. **Подготовка.**
   ```
   python bench.py prepare
   ```
   Выгружает пустую конфигурацию через ibcmd, собирает исходники 29 проектов, запускает EDT, импортирует проекты
   через EDT MCP и проверяет каждый. Повторный запуск пропускает готовое.
6. **Проверка.**
   ```
   python bench.py check
   python bench.py score --task B1 --canonical
   ```
   `check` проходит по настройкам, PRISM, платформе, Claude Code, ключу и EDT. Эталон задачи должен получить `"solved": true`:
   это значит, что оценщик и платформа работают.

## Запуск теста

Параметры по умолчанию - раздел `run` в `settings.yaml`. Любой из них перекрывается ключом:

```
python bench.py run                                             # всё из settings.yaml
python bench.py run --models claude-sonnet-5-5 --variant composerun --tasks B1-B20 --runs 1,2,3
python bench.py run --variant full --tasks B21-B29 --runs 1    # полный набор на новых задачах
python bench.py run --score-only                                # только оценить готовые прогоны
python bench.py agent --task B1 --model claude-haiku-5-5 --variant edt16 --dry-run   # условие без вызова модели
```

Серия возобновляемая: прерванную серию продолжает та же команда, готовые прогоны пропускаются.

### Варианты

`python bench.py variants` печатает список. Кратко:

| Вариант | Что видит агент | Набор на сервере EDT |
|---|---|---|
| `notools` | ничего: условие и описание метаданных в подсказке, один ответ | - |
| `edt16` | 16 инструментов EDT MCP: метаданные, код, запись модуля, ошибки, запросы, справка | 16 |
| `tools6` | шесть из них | 16 |
| `set30` | набор для регулярной работы: 30 на сервере, 24 разрешены | set30 |
| `groups` | встроенные группы плагина: видна core, остальное агент раскрывает сам | groups |
| `full` | все 102 инструмента сервера, опасные запрещены | full |
| `compose` | обёртка: пять составных инструментов, EDT напрямую не видна | 16 |
| `composerun` | обёртка + `run_code` (запуск кода на временной базе) | 16 |
| `composerun2` | то же со строгой проверкой объявления функции | 16 |

Перед серией `run` сам переключает EDT на нужный набор (EDT перезапускается). Новый вариант - запись в
`stand/variants.py`.

### Несколько экземпляров EDT

Набор инструментов включается на весь экземпляр EDT. Чтобы гонять разные наборы одновременно, заведите несколько
экземпляров в `edt.instances` (своя рабочая область и свой порт у каждого) и выбирайте их ключом `--edt`:

```
python bench.py --edt 2 prepare
python bench.py --edt 2 run --variant full
```

Одновременные серии на одном экземпляре допустимы, если вариант требует один и тот же набор: проект задачи
занимает один прогон за раз. Лицензии 1С делятся через `platform.license_slots`.

## Результаты и отчёт

Каждый прогон - каталог `results/<модель>__<вариант>/<задача>/run<N>/`:

| Файл | Что в нём |
|---|---|
| `prompt.txt` | условие, которое получил агент |
| `transcript.jsonl` | журнал Claude Code (stream-json): все ходы и вызовы инструментов |
| `candidate.bsl` | модуль решения |
| `meta.json` | ходы, токены, время, вызовы по инструментам, какая модель отвечала на самом деле |
| `score.json` | вердикт оценщика: пройдено тестов, ошибки компиляции, журнал тестов |

```
python bench.py report                       # B1–B20
python bench.py report --tasks B21-B29 --out report.md
python bench.py report --csv
```

Цена задачи считается по ценам из раздела `prices` настроек. Столбец «подмен» показывает ответы, где шлюз вернул
другую модель, чем заказана: такие прогоны стоит удалить и снять заново.

## Новые задачи B21–B29

Девять задач написаны после настройки обёртки и в настройке не участвовали. Формат - как у PRISM
`tasks/category_b`: `task.yaml` (условие), `config_spec.yaml` (метаданные), `fixtures.yaml` (данные), `tests.bsl`
(скрытые проверки), `canonical.bsl` (эталон). Эталоны проходят оценщик стенда: `python bench.py score --task B21 --canonical`.
